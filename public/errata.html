E-001 — Price freshness matched two windows

Affects schema 0.1.0 · Corrected in 0.1.1 · Filed 18 November 2026

What was wrong. Notes accompanying schema 0.1.0 put revalidation windows in a single table headed as tiers, and that table included a commercial row of 30 days. commercial is an estimate kind, not a tier. A vendor price is vendor_reported (6 months in the same table) and commercial at once, so the notes named two windows and no rule for which one applies.

What to do instead. Use schema 0.1.1. Windows exist on both axes. An estimate-kind override wins when one is defined. commercial is 30 days. A vendor price therefore revalidates every 30 days, and the 6-month vendor_reported default applies only when the kind has no override.

What did not change. Tier weights, the claim fields required in 0.1.0, and records that leave scope unset. Adding scope in 0.1.1 is a compatible extension, not part of this erratum. The archived text is /standards/evidence-tier/0.1.0.

Research reference. Not medical advice, not a dosing protocol, and not an offer for sale. The tools run on americanpeptide.com.
